ARCHITECTURE / THE SOURCE BOUNDARY

The instruction
starts as bits.

Executable instructions are authored as literal binary digits. Ordinary host tools package those values, inspect them, and test them in the intended execution environment.

  2. 02 / HOST TOOLByte packingB8 2A 00

  3. 03 / ENVIRONMENTCPU executionBIOS real mode / Linux x86-64

What the host adds.

The canonical 512-byte image

boot/boot.bits contains the entire sector: instruction bytes, message data, explicit padding, and the 55 AA signature. Packing this source reproduces the image without adding bytes.

Gallery packaging

Smaller payloads receive non-executable sector padding and signature data, or ELF headers for Linux. Multi-sector images combine a separately handwritten loader with separately handwritten second-stage instructions.

Host metadata is generated. Target instruction encodings are not generated by an assembler or compiler.

A small bootable system, with explicit limits

The boot program initializes segment and stack state, prints through BIOS, mirrors output to COM1, and halts. The disk loader reads a second stage; the interactive monitor offers a small command set. This is an educational bare-metal environment, not a complete production operating system.

Protected-mode work, custom interrupt handling and executable loading require separate implementations and execution tests. The current roadmap distinguishes completed work from research.
