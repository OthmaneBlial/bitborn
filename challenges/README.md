# Twenty-two binary challenges

Each `start.bits` and `solution.bits` is a canonical, directly authored sequence of eight-digit binary tokens. Comments describe the bytes; they do not generate them. `catalog.json` supplies learning goals, edit rules, hints and explanations. `targets.json` records reviewed byte sizes and SHA-256 hashes for both sources. `tools/build_challenges.py` only packages those existing bytes for the website.

The original four five-stage paths move from registers and byte order through arithmetic and control flow, then stacks and flags, and finally memory and boot architecture. A fifth path adds two [measured optimization puzzles](../docs/tutorials/optimization.md): clearing registers (14 → 12 bytes) and reusing a value (11 → 10 bytes), each with two distinct reviewed solutions. They preserve seven locked setup bytes, permit a shorter tail and check the complete payload size. The interactive validator checks register, flag, memory and output goals, accepts alternative solutions within each stated budget, and stops after a bounded number of steps. It is a teaching model, not a full x86 emulator.

Twenty-one primary real-mode fragments load at `0000:7E00` through `boot/loader.bits`; two optimization alternatives and two optimization starts use that same loader in native tests. The loader establishes `CS=DS=ES=SS=0` and `SP=7C00`; fragment instructions explicitly initialize the general-purpose values they use. CLI keeps their final HLT stopped. `repair-boot` is a copy of the actual 512-byte boot source with exactly three deliberately damaged opcode bits. Its reviewed solution is byte-identical to `boot/boot.bits`.

Run `python3 tools/build_challenges.py`, `node tests/test_challenges.mjs` and `python3 -m unittest tests.test_challenges`. The Python test boots only the 26 curated cases in isolated QEMU guests and checks actual registers, flags, memory and VGA/serial output. The six optimization sources also have independent NDISASM boundary checks and unchanged instruction-RAM checks; PUSH/POP's remaining stack word is verified. No downloaded or user-edited program executes on the host. `node tests/browser_challenges.mjs` checks all twenty-two completions, both optimization alternatives, hints, shared URLs, local progress, hostile input and responsive keyboard use in a real browser.

Progress lives only in the current browser's local storage. There are no accounts, analytics or network submissions. Deleting site data clears the local completion record. Source and explanations were developed with AI assistance and checked with independent QEMU execution.
